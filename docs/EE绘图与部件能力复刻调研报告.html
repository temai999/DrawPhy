复刻 EE 的「绘图 + 部件」能力：
把科学制图做成一个可快速出图的网页编辑器

版本 v1.0 日期 2026-11-04 范围 EE 绘图与部件 → Web 编辑器 → 可导出图片 交付 本报告 + 可运行代码（D:\Trae CN\myPro\DrawPhy）

一句话结论：EE 好用的不是「功能多」，而是把三种能力缝在一起——徒手就画（零参数建模）、智能几何（自动捕捉端点/交点/切线，画完即准）、部件即积木（符号可拖入、可改色、可缩放不糊）。三者共同把「画一张物理图」的时间压到几十秒。

技术结论：这个体验可以在浏览器里复刻，且不需要引入框架或构建工具。选 SVG 场景图 + 参数化部件 + 自带捕捉引擎，一套模型同时喂给画板、缩略图和导出管线，矢量导出与 2×/4× PNG 都免费获得。

当前状态：代码已落地并跑通——87 个部件 / 6 类、17 个工具、完整拖动体系；17 项逻辑自检、22 项交互自检（合成指针事件跑真实拖动链路）与 PNG 光栅化全部通过。布尔运算与普通图形的任意角度旋转仍属二期（见第 8 节）。

1. EE 的能力拆解：四层模型

把 EE 的绘图能力按「越往下越像基础设施」的顺序拆成四层，复刻时就能逐层对齐，而不是对着截图仿界面。这个拆解是我在复刻过程中形成的工作模型，用于指导实现优先级；EE 内部实现细节并未公开，因此下文只描述可观察到的交互与结果。

1.1 三个真正决定效率的设计选择

  • 先选工具、再落笔，不要弹参数框。教师的动作是「我要画一条线」，不是「创建一个 LineObject 并填写 x1,y1,x2,y2」。EE 的所有绘制都是拖动即出，属性事后在侧栏改——这与「先参数后图形」的 CAD 范式相反，也是它比 CAD 快的原因。
  • 几何关系在落笔时自动成立。用户不需要知道「约束」这个词：靠近端点就贴上去，方向接近水平就锁正交，两线交叉处可直接从交点起笔。这层「隐性约束」是复刻的第一优先级，而不是图层、样式之类。
  • 部件是「可改的单色符号」，不是图片。同一个电池符号既能当电路元件，也能被整体染成红色表示断开位置；缩放后线宽不糊。用位图贴图会立刻失去这两个能力。
说明：本节及下表中的「EE 做法」是对其公开文档与典型使用方式的能力归纳，并非对 EE 内部实现的反编译结论；个别细节（例如部件是否支持参数联动）以你实际使用为准，若与实际不符，我可以按你的口径修正后重出一版对照表。

3. 技术选型：为什么是 SVG 场景图，而不是 Canvas

这是整个复刻里唯一一个「选错就要重写」的决定。三条硬指标：矢量导出、文字清晰、对象可被精确命中与捕捉。Canvas 在前两条上都要额外补课（文字锚点要自己算、导出矢量要重画），而 SVG 天生自带。

维度SVG 场景图（采用）Canvas 2D
矢量导出DOM 即矢量，序列化即为 SVG 文件需自建矢量导出器，或只能出位图
文字与上下标浏览器排版，tspan 原生支持手写排版，上下标需逐字测宽
命中与捕捉几何在模型里，命中算数学而不是像素同样要算几何；像素回读代价更高
万级对象性能会退化，需分层或改为 Canvas 混合更强，但本场景（单页几十到几百对象）不需要
实现成本低：一个渲染器同时服务画板/缩略图/导出高：三套绘制路径要各自维护

结论：教学图的规模远小于「万级对象」，选 SVG 换来实现简单与导出免费。若未来要做「整册教材批注」（数千对象同屏），再按图层做 Canvas 混合即可，对象模型不用改——这也是把几何放在模型层而不是 DOM 层的好处。

4. 架构：一条数据流，三个消费端

关键设计：没有「视图对象」。画布上的一切都不是 DOM 节点身份的持有者，每次重绘都是「模型 → 字符串 → innerHTML」。这样做的代价是每次交互重建 SVG（本场景可接受），收益是没有状态双写——撤销、加载工程、批量变换都不需要同步 DOM，也解释了为什么一千多行代码能覆盖住 17 个工具。

5. 对象模型：所有东西都是同一个 obj

// 一个对象的最小形状
{
  id: 'l7', type: 'line',          // line | polyline | rect | circle | ellipse | arc
  x1: 120, y1: 300, x2: 420, y2: 300,   //  | arrow | text | dim | angle | part
  style: { stroke: '#22303c', width: 2, dash: 'solid', fill: 'none', opacity: 1 }
}

// 部件不是图片，而是"带矩阵的图元集合"
{ id: 'p3', type: 'part', partId: 'battery', x: 260, y: 580, s: 1.5, rot: 0, flip: false }

// 部件定义（parts.js）：局部坐标里的图元数组，可继承实例样式
{ id: 'battery', name: '电池', cat: '电学', w: 64, h: 32,
  shapes: [ L(0,16,22,16), L(22,4,22,28), L(30,11,30,21), L(30,16,64,16) ] }

三个由此获得的性质：

  • 部件与图形地位相同。选中、缩放、镜像、群组、层级、导出都走同一套代码，不需要为「符号」写特例。
  • 改色即改全部。部件内每个图元默认继承实例 style.stroke，所以一个电池能被整体染红；需要实心的地方（物块、箭头尖）用 fill:'solid' 标记，跟着描边色走。
  • 缩放不糊。部件靠矩阵变换，导出时仍是矢量。

6. 部件库：先立规范，再堆数量

部件最容易做成「一堆写死的坐标」。规范是：局部坐标原点在左上角，尺寸 w×h 由包围盒决定，所有图元落在 0..w / 0..h 内，线宽走实例样式。这样缩略图能自动按比例缩放居中，放置时用「中心对齐光标」，翻转与旋转围绕几何中心。

6.2 拖动体系：EE 的手感八成来自这里

EE 让人觉得「快」，不是因为它画得快，而是因为摆得准：所有东西都能拖，拖的时候自动对齐，线会粘在元件上。本轮把这条链路补成了完整体系，并逐条做了自动化验证。

实现上有个关键取舍：绑定不存绝对坐标，存相对宿主中心的偏移（bind = { x1:{id,dx,dy} }）。若存绝对坐标，宿主缩放后线端就对不上；存偏移则缩放天然成立，且只需在每次重绘前统一重算一遍（applyBindings()），不用给每个对象挂监听器。

7. 捕捉引擎：优先级比精度更重要

捕捉的难点不是「算出最近的点」，而是多个候选点重叠时选哪一个。若栅格与端点同时命中，选栅格会让用户的「贴端点」意图落空，画出来的图差一两个像素、看着就是不对。所以本项目给几何锚点一个与捕捉半径成正比的优先级奖励：

score = 距离 − (几何锚点 ? 捕捉半径 × 0.35 : 0)   // 越小越优先
// 候选池：栅格 → 端点/中点/圆心/象限/中心 → 交点（仅近邻对象之间两两求交）
候选类型来源优先级
端点线段两端、折线顶点、矩形四角、部件包围盒角最高
中点 / 中心线段中点、折线各段中点、矩形中心高
圆心 / 象限点圆、椭圆、圆弧高
交点近邻对象的线—线、线—圆、圆—圆高（只在 2.2 倍捕捉半径内计算）
正交 / 15°相对上一点的方向约束（3° 自动磁吸，Shift 强制 15°）仅当无点命中时生效
栅格固定步长取整（默认 20 单位）最低

移动与缩放也复用同一套逻辑：拖动选区时，包围盒四角会尝试对齐到其它对象的锚点，偏差在 7px 内即吸附——这正是「把两个元件摆成一条线」这类高频动作的省力点。

8. 已实现 / 未实现的边界

8.1 现在的边界（必须说清）

  • 修剪只支持直线。折线、圆、矩形被别的对象打断后无法「点一段删一段」。做法是把 doTrim 里的参数化逻辑下沉成通用的「按交点重采样」，二期可扩到所有开放曲线。
  • 普通图形不能任意角度旋转。部件已可用旋转手柄自由旋转（Shift 吸附 15°），文字仍走 90° 步进；矩形、椭圆、圆弧要转任意角，需要引入「对象自带角度 + 角度感知的包围盒」，改动面较大，放到二期。
  • 填充是「整对象上色」，不是「点内部填种子区域」。对矩形/圆/多边形够用，对「两条线与圆弧围出的区域」不行——那本质上需要布尔运算，见下一条。
  • 布尔并/差/交未实现。这是 EE 类工具里「画不规则图形」的关键，需要平面多边形布尔库（如 martinez），属于二期最大的一块。
  • 部件是「静态符号」，没有参数联动。EE 的控制器/占位符能做到「改一个值，符号跟着变」（如滑动变阻器滑片位置）。这需要在部件定义里加参数通道，是二期设计重点。
  • 无图层面板与多页。当前 z-order 靠数组顺序，置顶/置底够用，但画复杂装置时会想要「把电路放一层、标注放一层」。

8.2 二期路线（按投入产出排序）

  1. 部件参数化（性价比最高）：给部件定义加 params，先做滑动变阻器滑片、可变电阻、透镜焦距指示，让「一套符号覆盖一类题」。
  2. 布尔运算 + 种子填充：引入多边形布尔，打通「不规则区域上色」，顺带解锁修剪的通用版。
  3. 普通图形的任意角度旋转：把部件的旋转能力下沉到对象层——图形加 rot，包围盒走旋转矩形，手柄跟着转。
  4. 图层与多页：对象加 layer，渲染按层分组，导出按页。
  5. 导出增强：PDF（打印友好）、按选区导出、透明背景、批量导出整册。
